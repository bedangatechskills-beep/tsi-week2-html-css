## How to use these notes

1. Open the `W2D1` folder in VS Code (File → Open Folder).
2. When a note shows `File: index.html`, make a **new file** with that name in a practice folder, type the code
   (do not paste it), save, and right-click → **Open with Live Server**.
3. Before you save, read the **Predict:** line. Guess what you will see. Then check.
4. Each note ends with **Check yourself** questions. There are no answers on the page on purpose. Find the answer
   by running code, or ask in class.
5. Images: the snippets use files like `images/momo.svg`. Copy the `images` folder from any classwork folder
   (for example `classwork/D1-09-broken-paths/images/`) into your practice folder, next to your HTML file.

## The bug tags you will see in every note

Every planted bug in class has a tag. It tells you **how** you can find it.

| Tag | Meaning | Tool that shows it |
|---|---|---|
| **V** | You can **see** it on the page | your eyes |
| **D(HH)** | HTMLHint underlines it in VS Code / Problems panel (Ctrl+Shift+M) | HTMLHint with the class `.htmlhintrc` |
| **D(F12)** | Only the Elements panel shows what the browser actually built | Chrome DevTools |
| **D(URL)** | Submit the form (`method="get"`) and read the address bar | the URL bar |
| **D(LH)** | Lighthouse → Accessibility report (works offline) | Chrome DevTools, Day 2 only |
| **D(W3C)** | Only the W3C validator reports it | validator.w3.org (Wi-Fi bonus) |
| **H** | Hidden on Windows, breaks on a real Linux server (file-name case) | explained by the instructor |
| **R** | **Rule check**: no tool fires; you must read the code against the rule (e.g. "one h1", "no heading jumps") | your brain + the notes |
