## How a bug-hunt works

1. The README says how many bugs there are. Find **at least N−2**.
2. Repair each one, save, and check the page again.
3. Write your scoreboard line: `I found __ / N. The reveal taught me: ________`
4. The instructor shows every bug in the **reveal**. No bug goes unexplained.

Bugs hide in different ways. The tag tells you which tool shows them:

| Tag | How you see it |
|---|---|
| **V** | on the page, with your eyes |
| **D(HH)** | HTMLHint squiggles in VS Code (Problems panel: Ctrl+Shift+M) |
| **D(F12)** | Chrome F12 → Elements |
| **D(URL)** | submit the form and read the address bar |
| **D(W3C)** | the W3C validator (validator.w3.org, needs Wi-Fi) |
| **H** | hidden on Windows; breaks on a Linux server (capital letters in file names) |
| **R** | rule check: read the code against the rule |
